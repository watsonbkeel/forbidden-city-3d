## Recommended reviewable staged design

Use fresh sequential processes under the same 256 MiB old-space, semi16, 350 MiB full-Node-tree ceiling, the same public base/candidate/source lock, and no concurrent fixtures. No implementation is authorized by this document. A top-level total wall-clock budget must remain at most 180 s across phases, not reset into two independent 180 s allowances.

1. **P1: invariant old routes and terminal restoration.** Reconstruct the exact approved subset, one CM, all A checks and controls. Run the unchanged 68 original variants before and after attaching the exact same candidate, with all existing original assertions, equal results/frame hashes, full compound state and resource-reference witness. Immediately remove the private candidate, restore original CM lengths/grid, assert exact original snapshot, then run the full approved resource cleanup with all event/ownership checks. P1 is not green until its cleanup, process/reader exit, locks and resource budget close.
2. **P2+C: candidate routes followed by C on the same live objects and CM, then terminal restoration.** Only after P1 green, reconstruct the same byte-locked subset and candidate in a fresh process with one CM, rerun A/real mesh checks and retain the same per-run before/after full state/reference witness. Execute exactly the current 16 new positive variants, four closed-side negative variants, valid closed central backplate negative and removal/restored-route positive, using the unchanged real controller, routes, frame recording and assertions. Keep all old colliders. **Without reconstructing or replacing the candidate or CM, and without any extra reset beyond the already-approved negative-control removal, continue directly to the existing C checks on those same exact live references after every new route and counterfactual has returned.** Retain every old occluder, all existing eye support, own-leaf/hollow-opening/central-context tests and all seven named-object/actual-face-point first-hit requirements. Keep Front/Back/DoubleSide/null handling and all negative controls. Only then restore and clean up fully. No old variant is dropped: all 136 remain in P1. New phase selection must not duplicate their count or call P2+C a complete original-zone test. This is spatial readability only, not final production geometry, imagery/PBR or a complete-zone claim.

**Explicit limitation:** this two-process proposal is not equivalent to the original complete single-process A→136 old-route variants→new routes→C lifecycle. In particular, P1's old route sequence and P2+C's subsequent new routes do not share one live candidate/CM. P2's new route sequence and C do preserve exact live candidate/CM continuity. A future full original one-process CI gate, or a separately accepted narrower design gate, is still needed; do not label this split proof as the untouched original full probe passing.

Across processes, do not equate random UUID/resource identities. Each phase must perform its identity/ownership comparisons within its own live scene. The cross-phase witness is the exact immutable public code/assets, candidate script/parameters and original route source hashes, plus identical deterministic semantic summaries where already defined. Each phase must independently assert its actual original state before/after; this preserves the original identity semantics rather than weakening them to a loose cross-process comparison.

P1 still approaches the ceiling. A minimal explicit collection checkpoint can be reviewed at safe completed-route-group boundaries: only after every original route consumer/assertion and frame hashing has returned and bounded mock cleanup has finished, never during replay or between an original assertion and its input. Retain all reports, comparison snapshots, live resources and object-reference maps. Existing `--expose-gc` is already enabled. A full collection may reduce dead test allocations but is not guaranteed to reduce RSS and is not a product optimization. Pure order/retention tests plus an exact script diff must precede any new actual window. If the proposal cannot satisfy the original budget, stop rather than raise it or try heap parameters.

## Fixed implementation contracts required before any executable revision

- **GC fixed points:** in P1 only after each entire original `runYuhua`, `runEast` and `runWest` call has returned, including all original assertions and bounded-mock release; never after route-capture `rows.push` alone. In P2+C, any collection must be declared at a fixed point after the private replay helper has returned its fully asserted/hashed result and the caller has stored it, or after a completed entire new-route group. Never select collection time based on RSS. Keep strong references to every actual scene, CM, candidate, library, report, old comparison capture and resource-reference map; do not clear or replace them to meet the budget. Check relevant snapshot/reference invariants before and after an execution-only collection. GC/markers must not change the simulated clock or run inside controller updates.
- **One aggregate monotonic deadline:** the total 180 s includes both process launches, execution/GC, inter-phase input/hash verification and terminal restoration/cleanup. It is not two monitor resets. The orchestrator must stop the active verified group when the remaining aggregate budget expires; live missing-RSS/unknown identity remains failure. The fixed 350 MiB accounts for runner, worker and all known live descendants; it is not a per-worker limit. P1 must have terminal successful cleanup, process/reader closure and full input/index lock equality before P2 can launch.
- **Fixed assertion ledger:** enumerate all original 136 variants with their original assertions/frame hashes, new positive16, closed-side negative4, central counterfactual2, every A reserve/contact/intersection/source-ground/real-old-face negative assertion, and every C support/eye/leaf/opening/central-context/seven-target first-hit assertion. Completion is recorded only after its caller's assertions have returned. The ledger cannot accept only a replay callback or stage-entry marker. These are diagnostic variants, not new formal test-count claims.
- **Same P2+C candidate/CM:** use the same actual references and keep all old colliders/occluders. The sole allowed CM tail removal/grid invalidation is the existing line66 operation that removes the private central backplate negative control; do not add a phase-boundary CM rebuild/reset. Its private mesh removal, restoration-route positive and all original resource cleanup checks stay present.
- **Fresh immutable authorization:** bind the new reviewed plan, every executable script and actual input lock by exact hash, and require one exclusive batch marker. Do not reuse the old authorization/started files. Any nonzero exit, input drift, unknown/nonterminal process, missing required receipt or unsuccessful/missing cleanup makes the batch red, even if a child exit code alone is zero. No later phase may start after that result.
- **Pure orchestration regressions before fixtures:** exercise the actual orchestration wiring with mock process observations for aggregate deadline during launch/GC/bridge/cleanup, unknown RSS, cleanup failure, missing receipt, input drift, late/residual descendants, and success. All failure cases must prevent the P2 launch. Preserve original route assertion bodies and inspect the complete diff; no production fixture may run until the new immutable package is independently reviewed and root grants a new unique window.

The phase orchestrator must be independently reviewed for: first failure prevents later phases; aggregate 180 s cap and unchanged 350 MiB tree accounting; every known descendant and reader closes; missing RSS/nonterminal cleanup is a nonzero outcome; strict input/index pre/post lock and exclusive once marker; all old/new/C assertions remain traceably present. Stage markers and per-variant evidence should identify the exact last completed assertion without changing route execution.
