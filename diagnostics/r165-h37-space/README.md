Cleanup after a limit violation may finish later to retain honest failure evidence; such a run cannot pass.

The cgroup parser accepts a v2 hierarchy root only when the mount is rooted at `/`, both non-root-only memory interfaces are absent, and the memory controller is explicitly listed. Namespace/subtree roots and ambiguous/partly missing interfaces fail. Root physical memory uses the actual MemTotal/MemAvailable readings, not an invented cgroup current value. See the Linux kernel cgroup-v2 memory interface documentation: https://docs.kernel.org/admin-guide/cgroup-v2.html .

RSS limits are sampled diagnostic contracts, not kernel-enforced caps or proof of every instantaneous peak. Wrapper VmHWM additionally detects its own lock-period peak; observed non-Node identities persist across samples and unknown/zombie/residual state fails. Synchronous lock tools (`git`, `node --version`, `fc-list`, `fc-conflist`) use bounded subprocess calls that wait and reap; their intervening instantaneous combined peaks are not continuously sampled. No extra fixture or asynchronous helper is launched during those calls.

Font inputs retain the original native default system-font behavior.
