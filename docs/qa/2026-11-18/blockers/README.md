## 已修及已排除的误报

- **保和殿北阶元数据**：三大殿的建造器在销毁时漏清三条北阶记录。如果建造器继续被引用，调用者仍能看到旧元数据。只清空自己的数组，不改台阶、建筑或材质。真实三大殿共用台基连续建造/销毁两次，73件几何及58件自有材质按预期释放、15件库材质不释放。若整个实例已不可达，垃圾回收可回收它；未发现 GPU 泄漏。此问题是检查时另发现的，**不是**把第248条的“材质所有权夹具错误”改称为产品错误。[释放收据](baohe-lifecycle.json)
- **地图检索**：原159个核心卡片的身份通过已有冻结资料原样重建；另外验证5张后来正式加入的主卡、136补录、4组桥梁设施的实际按钮。所有区域按钮的可见数与计数器对得上，同时保留搜索、详情、返回、双“皇极殿”及无意外传送断言。原19/25，现25/25。
- **昭德门**：加入使用真实注册世界的16条玩家驱动与8条受控破坏实验。只临时改变目标坡面，测试后恢复对象与所有权；未解绑生产保护或让不合法的复制对象通行。本文件升至50/75。
- **只剩历史重放的异步异常**：第180条来自加载历史屋脊模板时的顶层异步补丁失配。当前实际殿堂的构建与销毁不调这段历史补丁；仍保留原重放失败，不称历史已通过。
- **建筑几何**：[20项逐条核查](geometry.md)。比如昭德门有2个廊端，另2个属于贞度门；六窗72根实格棂可从组成网格查到。熙和门现有牛腿三角面非退化。原差异仍保留，另用3个当前行为测试验证，不更新历史指纹。

## 三佛：默认入口与试玩不是同一个版本选择

**合并本分支也不会让无参数入口自动换佛像。** 裸 URL 仍走原有展示，明确的 `?triad=texture-first` 才进入用户曾试玩的三尊浅浮雕。既有试玩 README 和 R379 均保留默认关闭，公共网络测试要求默认不请求三佛原画；此轮不改这些约束，也不把触屏模拟接受度扩张成桌面或全端批准。当前线上 Pages 没有部署本候选。原始三幅 PNG 合计 8,253,405 字节；到达或预载外西路后才可能请求，不是首屏资源，也不是只有踏进殿内才会请求。隔离试验只把无参数改为默认试玩，保留原断言时切换器从4/4变为3/4，且与公开版默认零原画请求的R361契约相冲突。

在本分支本地运行，以下命令直接打开试玩入口，无需手输查询。用无参数的同一地址打开可对照旧像；失败/切换区域会按既有生命周期回收与降级。

```sh
VITE_BASE=/forbidden-city-3d/ npm run dev -- --open '/forbidden-city-3d/?triad=texture-first'
```

若要以后把试玩切为普通入口，应先在相同的**生产包**对照无参数与试玩，记录桌面、触屏/实机首帧和大佛堂实景、每尊部分失败后的有效回退、出入区后资源回收与冷加载；保留明确恢复旧像的方法和可回滚提交，再单独审阅默认请求契约。不能删除原测试把“未默认启用”变成“默认已验收”。
