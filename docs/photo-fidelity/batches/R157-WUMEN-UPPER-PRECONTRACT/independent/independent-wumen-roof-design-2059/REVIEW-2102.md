# 亭翼屋面旧边界与三段参数化：独立只读设计审

**结论：旧边界记录与现源码／公式相容；“脊—承托边—檐口”水平映射可继续只读数值研究，但 2057 尚不是可实施的屋面合同。不得据此生成获批实体或接生产。** P0 未发现；P1 为承托边定义、实际三角采样、Y 保持口径及完整数值／基线缺项。本轮没有运行 capture、Node 测试、FP、World 或 CPU，与备份没有重任务并发。

## 1. 身份及旧 bounds 能证明什么

`ROOF-DESIGN-FREEZE-2057.json` 八路径逐 SHA 相符。设计 SHA `962b5a5cf6c2fa086e82f948b4dedac38047b2fb1f7787aef5c062f0313a1a34`；旧捕获 JSON SHA `8e9d065d81ce89f6f43d3cde904e72c47a717cc05197243d32aa2ac7b9b10843`；脚本 SHA `9fddf5e8270494328147208400838b532e9f923048717d557beb6bfcc31b9cab`。原 exit 为 0。此轮只读复核，不将作者 0.31s 捕获说成本轮重跑。

独立核对 JSON 的 15 个 group 记录与原 log 全部 path、bounds、mesh 数、top/eave 一致，各 group bounds 恰等其所列 mesh bounds 并集。其中真实屋面组为 **7：主楼 1、翼 2、亭 4**；另含亭身／整翼／横连记录，整翼与嵌套翼 roof 不可相加重复计数。四亭相应 position 属性指纹／计数相同，两翼 roof 相应指纹亦同，实际位置各自不同。

**翼 roof 的 userData eave/top 是父局部值**（6.5876890973／13.6899576187），必须加 wing parent Y=12.3；亭 roof 的顶点已含原 19.8 基准，group Y=0。不能把两类数字同列而漏／重复加台顶。

此前独立代码公式经对应 Float32 存储换算，恰得到上述亭／翼实际最高点，解释了小的舍入差；这不是对新形体的预测保证。eaveY 是生成器命名基准，亦不等于所有带翼角／椽头顶点的统一 Y。

**此捕获不是完整几何／材质金样。** 它保存 position SHA、顶点及 index 数量、bounds、部分 group metadata；没有每项 normal／UV／index 字节、drawRange、所有 mesh 矩阵和有效材质／可见状态。captureGate 使用 tileSize/aspect=1 的白材质 fixture；不能据其证明生产纹理 UV／材质。下一实体 TDD 前须另冻结完整实际基线，不能后改当前旧记录去迎合候选。

## 2. P1：先定义“墙轴／承托边”，不能把 19m 柱轴直接作 roof knot

实际旧亭：
- 柱轴宽 P=11，半宽 5.5；
- 内红实体半宽 4.7，北贴面中心 Z=4.8、前皮 4.9；
- 梁外宽 P+.4=11.4，半宽 5.7；RoofBuilder 输入 footprint、下斗拱和 fan 也是 11.4。

旧翼相应是柱轴 39.4×13、roof 输入／梁外边 39.8×13.4，而不是所有层共用同一个“墙”。新三段参数表必须分别命名**柱心、实体墙皮、梁／斗拱承托外边、roof footprint、tile 在该边的交线、soffit 在该边的交线**，并列旧→新数值及 Y。约 19m 的源轴包络不自动给出任何一个新的围护／檐口外皮。

四亭自己的非正方形宽深以及两翼 π/2 父旋转必须各自处理。任一层至少列脊部轮廓、实际承托环、檐环；相邻面使用同一条共享边与同一映射，不能逐面独立拟合后只看轴向单调性。

## 3. P1：函数命中墙轴不等于三角网格实际命中

旧 `hipSurface` 的 low tile 为 6 段 t 采样，soffit 则从 tw 另行开始；两者不是同一个网格。旧上层亭 tw≈.7830802603、翼 tw≈.8064516129，均在 tile 的 [2/3,5/6] 段内部，不是 tile 采样行。

仅按源码二次剖面、取不带角部 lift 的边中线，分段直线在墙轴处与解析剖面的差约为：亭 **.017557621m**、翼 **.012920344m**。这是公式层诊断，不是本轮实际射线测量，也不能直接称旧承托存在相同大小“洞”；它说明单靠函数相等或 maxY 不足以证明实际三角交线。

新方案的关键 knot 必须落在**实际 tile／soffit 网格的共同分段边**，以实际三角边／平面交点复验。若为此插入采样行，就要声明拓扑／三角数量和对应 Y delta；不能同时说原三角列表原字节保全。还需检查圈边相接、四角共边、层间交错、非零面积与法线朝向，不只检查抽样端点。

## 4. P1：“保持旧 Y”须分层，不能同时承诺所有原顶点 Y 不变

2057 的方向优于直接改 width/depth 后调用默认 builder，但以下约束不同：

1. **命名结构锚点／无 lift 基础剖面**：可提议保持旧工程 Y、厚度约定、斗拱／彩画带高，明确这是兼容目标，不是历史高度已证。
2. **角部 lift 场**：原 `f(s)` 含新边长与米制影响宽度 D；保同一个 s、固定 D 和扩大边长时，同序点 Y 通常变化。须明确选择／重新采样方式，列实际派生 delta，不能暗中拉大 D 后仍称固定旧尺度。
3. **固定半径重生脊管**：中心线水平变形会改变切线／Frenet 截面，TubeGeometry 的顶点 Y 投影不保证逐字相同；CatmullRom 插值还须验实际中间曲线／管面包络，不只中心控制点。
4. **宝顶／独立饰件**：保持原尺寸、detail low 及实物件数，只有明确平移；不得因漏传 detail 触发默认 high 额外兽件。

故应将“所有旧垂向样本不变”修为分角色合同：哪些锚点／基础剖面固定，哪些角部／管面实际 Y 为已声明派生 delta，各自限值和失败条件。仅保持最高点并不等于全屋顶垂向保全。

## 5. 正面积、法线与 UV 需要自己的有限变更合同

源码可直接证实：pavilion 上层 `corners(0)` 全退到 apex；旧 tile grid 首行每 quad 的一个三角形为零面积，low nU=10、四面至少 **40 个退化 tile 三角形／亭**。还可能有其它旋转体极点退化，须实际清点。新合同若要求全非零面，应显式移除这些退化三角，验证剩余表面闭合、不删微小但真实面；不能一面要求全正面积，一面声称旧索引／三角表完全保留。

法线应由新实际几何重算，并说明分段 knot 处是平滑还是有意折线。`computeVertexNormals()` 本身不证明不存在翻面／折叠／非预期硬折，需逐面朝向、有限长度及 shared-edge／corner 检验。

UV 亦需明确何为“按实际长度”：旧 tile 的 V 使用 64 段、**未包含角部 lift 的基准剖面**弧长表；它不是每条最终角部曲线的精确三维弧长。可保这个有界旧策略或另定实际表面策略，但必须明示与旧 UV 的 delta、材质尺寸／接缝规则，不得泛称原纹理保全。不要对 merged mesh 做整体非均匀缩放，也不能只换 normal 留被拉伸的 UV。

## 6. 可继续的最小数值交付与未关闭门禁

允许继续只读构造**每亭、每翼、每层**的完整参数表：
- 源轴／墙／梁外皮／承托环／脊／檐的空间标签与旧新 knots；
- 锚点 Y、基础曲线、lift 及管面 delta 策略、旧／新实际采样行；
- primitive／共享资源／目标计数表，旧完整属性金样计划；
- 非方形四角一致性、单位及父变换、各交线预期值和严格停止条件。

目前这些具体新 knots／接触数值尚未提供，因此数值门**未闭合**，本报告不是实体 TDD 或共享 RoofBuilder 修改授权。若抽取 generator 中间层，须先证明所有非目标（尤其主楼）原行为精确不变；采用隔离候选生成器也须证明旧配方可重放，不可另起一个未经审的新默认形制。

旧 188 脚、此处旧 roof bounds 和旧 rig 路线均不验新上层。最终仍须新实际全部柱脚／梁端／屋面接头、完整面 CPU，以及完整新上层在场的真实台面 FP；B 通过前不接生产，World／全套／构建／GPU另列。主楼、八接口未知身份、闭亭边界、南墙／阙门／世界原点均不被此设计批准改变。
