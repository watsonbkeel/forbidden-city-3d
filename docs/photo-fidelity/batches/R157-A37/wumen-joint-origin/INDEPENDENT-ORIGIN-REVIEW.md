# 午门 bbox / 正楼中心 / 南墙框架独立审查

2026-10-31 03:27 UTC。**只读来源审查；未改生产、未迁锚点、未建立运行承台，不是测绘或 GPU 验收。**

## 结论先行

1. **原 dimensions.md 的对象口径错误成立。** `638156366` 是含南伸雁翅和两侧马道的整体午门轮廓，其经纬度 bbox 中心不能直接当正楼中心。独立木构 part 和屋顶 part 一致将正楼放在当前项目坐标 `z≈−379.57`；现生产 `−419.6` 比它偏南约 40.03 m。
2. 官方 2021 平面的**局部柱网不需因此改值**。只将共同原点置于独立主楼 part 后，四亭对未参与选原点的 OSM 木构中心残差由 40.67–41.97 m 降为 0.72–2.06 m。这是同源地图与独立图像之间的有力一致性证据，不是 OSM 测绘精度证明。
3. 旧原点条件下“南亭撞阙门 / 需要 −522 南界”的阻断不应继续作为新框架硬事实。新框架名义支承南趾约 `−475.57`，仍在既有 `−500` 边界内；阙左、阙右原锚点不必被迁走以消冲突。
4. **不能只改 `WUMEN_Z` 上线。** 南城墙 `−425` 本身是旧文献混合 bbox 与台皮的推算；现城墙、马道终端和多处专用保护条件仍锁旧框架。正确来源关系尚未闭合，不允许凭空做 40 m 折墙、隐形承台或整体平移全城。

主木构比整体 bbox 北 `40.011182 m`；比现生产原点北 `40.034008 m`。量算的小数是算术复现精度，不是实物定位精度。保留中轴 `x=0`、暂用 `z=−379.6` 作为**可逆工程候选**也合理；没有证据支持把 `x=−0.162585` 当施工级偏移。

恢复表中坐标所需太和殿 way 638449347 bbox 原点是：

```
originLon = 116.39081395
originLat = 39.9158956
xr = -(lon-originLon)*85499
zr =  (lat-originLat)*111034
x = cos(2.13°)*xr - sin(2.13°)*zr
z = sin(2.13°)*xr + cos(2.13°)*zr
```

原文打印 `116.3906, 39.9159`，按实际复现框架偏 `(18.2617, 1.1681)m`，不是足以重算其表格的原点值；“旋转 −2.13°”的文字也缺主动/被动及坐标基约定。**应保存上述明确矩阵和来源对象，不把这处文稿错误解释为全城现坐标都应重新变换。**

## 2. 历史版本：没有“2026 建筑北移”的证据

已保存三份 OSM 官方 API history 原响应及 SHA：

- [整体 way history](https://api.openstreetmap.org/api/0.6/way/638156366/history.json)：v20（2026-09-29）仅将 `building=yes` 改为 `gatehouse` 并加文明标签；节点序列自 v10（2019-04-22）未变。当前该 way 所用节点最后编辑日不晚于 2020-06-15。
- [主木构 history](https://api.openstreetmap.org/api/0.6/way/638156994/history.json)：v2 仅加木材标签；当前节点最后编辑 2018-10-26。
- [主屋顶 history](https://api.openstreetmap.org/api/0.6/way/638156914/history.json)：节点序列不变；2021 年 v4/v5 把 `gabled → hipped → gabled` 来回改。其 `height=45`、`min_height=37` 等标签**不可被接受为午门实测高程或屋顶形制**。

因此当前原始几何与原文整理日（2026-10-11）的时间关系支持“原来就误认 bbox 对象”，而不是现在地图突然改了建筑位置。OSM 编辑时间不是建筑施工日期；本审查不推断真实建筑曾迁移，也不证明不同年代展厅隔墙相同。

## 4. 南墙为何是连带阻断，而非几米接头

原 dimensions 直接写：城墙 7/8 中心约 `−388`，却以整体午门 bbox 推南外皮 `−425`。**文献中 −425 的直接推导来源是午门 bbox，不应误说已证明它直接取自某个 barrier bbox。**

另一个同源佐证是 barrier way **638176319 v16**：整体 bbox 中点 z≈`−424.37`，但路径沿午门 U 型翼台绕到 `−473.75`；远离午门、`|x|>100` 的南墙节点 z 在约 `−387.69…−395.38`。城墙 8 / 7 独立实体 part 的 z 包络分别约 `[-390.08,-381.98]` / `[-395.38,-386.77]`。这揭示**不规则南线的 bbox 中点不等于城墙直段或外皮**。地图有倾斜、简化及轮廓口径，不能立即把全南墙改成统一 −388，也不能靠官方总长 961 m 唯一求其绝对南坐标。

生产代码关系：

- `Enclosure.wallLines()` 由 `PALACE_RECT.minZ=-425` 决定南墙；改 `WUMEN_Z` 不会迁它。
- `WumenAscentProfile.wallInterface.worldAnchorZ=-419.6` 和支承/墙 cap 仍绑定旧墙。
- `PalaceBuilder`、`WumenWingPavilionInstances`、`WumenOuterSideColumns` 等有原锚点 hardguard；`WumenTransverseLinks` 还会抛 retained-host mismatch。
- `WumenLinkSupport`、vertical profile、source plan registration 及锚点表/导航数据各有旧值。

所以新主楼处于约 −379.6 时，旧墙会在长翼中段侧接，而不是新的北横台/马道接合位置。只看新主楼 AABB 与旧墙不碰撞会漏过这个拓扑错误。**未核清前只能 source-axis / 隔离候选，不宣称完整世界已经闭合。**
