## 决定

**可接受为“保留 OSM 原节点的四个默认关闭几何研究实体”；不能接受为完成南部围合、接通午门或可运行候选。**

## 1. 独立验证已通过的有限内容

### 来源与非矩形拓扑

从原 OSM map JSON 重新读取节点，以太和殿 bbox 原点及明确矩阵转换，**没有用候选点表作为独立真值**。原 SHA `cc68b28b29088749f26642144160ab4100e1298d18c508acea37889fcb50d100` 与候选记录相符。

|---|---:|---:|---:|---:|
| 东南墙段 | 156149069 | 8 | 0 | 24 |
| 西南墙段 | 638206927 | 5 | 0 | 12 |
| 东南角台 | 156146468 | 7 | 0 | 20 |
| 西南角台 | 156145763 | 7 | 0 | 20 |

两条墙不是旧矩形边界的平移副本；保留了原折点、斜向和不等宽。两角台也没有用其 bbox 方盒代替。**角台不等于木构角楼中心**：本次参考木构与角台 bbox 中心相差约 3.42 / 4.93 m，区分对象是正确的。不同木构 part 的中心是否代表同一柱轴层仍需独立图像/平面注册，不能将当前选点的小数当角楼实测中心。

### 真实 mesh 与生命周期

独立只建立四实体并遍历全部 84 个三角：

- 四实体各自正有向体积；无退化三角；position/normal/UV 都是有限数。
- 按 `1e−5 m` 焊接坐标计边，每条边均恰有两个邻接面，四个单独壳体闭合。
- y 范围约 `[0,10]`；极小 `2e−14` 底部误差来自浮点旋转。
- 材质借用；ownedMaterials 为空，四个自有 geometry 仅释放一次。
- 当前 `colliders=[]`、`walkables=[]`，`runtimeEnabled=false`、`wholeObjectAccepted=false`。
- 原作者三项轻量测试独立重跑 **3/3 通过**。

这些证明的是正确挤出了给定 polygon，而不是它就是准确墙基、墙顶或真实收分后的砖墙。高度 10 m 确实为代码显式保留的工程值，不是借用 OSM height 标签。当前竖直等截面、单层材质没有证明实际墙身收分、下碱、墙帽、垛口及高程。

## 2. shared node 的确切含义与未接通缺口

独核两条墙的两端各有一条**连续共享边**，不是仅两个偶遇点：

| 侧 | 墙—午门整体源轮廓共边长度 | 墙—角台源共边长度 | 午门端 x 大致位置 |
|---|---:|---:|---:|
| 东 | 4.964 m | 5.710 m | −96.9 m |
| 西 | 5.167 m | 6.321 m | +93.6 m |

关键是“午门”这里指 **638156366 整体 U 型及马道轮廓**。共边位于马道外侧耳部，**不是新主台 x≈±63 的接口，也不是当前马道实际 mesh 已经相接的证据**。

当前旧马道随主中心整体北移后，回程/外折平台南边仍取 local z=−3：

- 东侧源墙午门端北点 z=`−385.113827`，新旧马道 floor 南界=`−382.565992`，纵向相差 **2.547835 m**。
- 西侧源墙午门端北点 z=`−386.774747`，对应相差 **4.208755 m**。

这是既有参数带与来源接口的实数缺口，不是已测所有栏板/踏步三角的最短净距。它已经足以否定“只整体北移旧马道就接好”。两侧值不同，也不能再简单以镜像同一 z 位消掉。

两墙与角台目前各为闭合独立挤出体，在共同竖直边界会有内部双面；顶面只共边、没有据此发现顶面重叠。若之后作为一个实体 union 或引入三角碰撞，需要显式处理内部界面/唯一 owner；不能将四个单壳闭合等同整个南部闭合。两角台以北的纵墙连接尚未在本候选建立。

### 马道资料交叉复读

亲看本轮重新下载的故宫官源 `https://img.dpm.org.cn/Uploads/pdf/2196/T00014_00.pdf` 印 14 页图文：第一段宽 6.2 m、水平长 15.3 m；第二段 25.59 m；第三段 25.5 m，宽度文字明确随城垣顶部。**没有依据把三段都固定为 6.2 m，也没有明确说第二段 25.59 m 不含平台。** 这支持将旧统一宽、额外加平台的解释保留为工程拟合，不能当已证源尺寸。2021 展厅平面可辅助端点注册，但不能补出未记载标高。

## 3. CPU 图、同相机及已关闭的诊断问题

亲看平面注册图、原 A/B CPU 图；独核两图 camera 的 position/quaternion/view/projection 完全相同。

- A：旧南墙、旧角楼、旧午门，加源轴线。
- B：四个源 polygon 实体，**旧午门形体平移**、**旧角楼形体移到参考木构中心**，加源轴线。
- B 尚不是官方柱网的新四亭/长翼/下层/马道联合几何；源轴标记还被放大显示。蓝灰材质也是诊断区分，不是实景材质配准。
- 全南段在画面占比小，不能凭这两张总览接受几米接缝、柱脚、墙顶或角楼承载。

原导出 camera.aspect=1.5，而 CPU 视口 960×540。逐行核实：CPU raster 的 x/y 使用同一个由 H 推出的 focal，**不会由这一差异导致此前猜测的 18.5% 横向拉伸**；实际潜在问题是 exporter 以较窄 aspect 的 frustum 预裁剪。

作者已另存 `cpu-southern-assembly-aspect-corrected/`。独立比较：A 的 68,748 个三角、B 的 66,696 个三角，修订前后数组逐项相同；两张 PNG 也分别逐字节相同。因此**本组视角没有实际漏边或比例变化**，口径问题已通过新元数据澄清。旧证据未覆盖。

以上全是 CPU/source diagnostic，不是 GPU 截图或官方照片同机位验收。

## 4. 非目标范围独核

独立逐文件计算 Git blob SHA，对基线 `3e9d5c92` 的 **575 个 src/data 原有文件**检查，内容全部相同。南墙 builder 目前在 scripts 隔离路径，未被 Enclosure 调度；三项测试也验证关键生产模块未引用它。

这证明本轮没有改写继承生产文件。它**不能代替**未来启用时的非目标 owner/geometry/UV/material/collider/support 精确比较，更不能将整个 Enclosure 从非目标检查中排除。今后的限定范围应是两条南横段、两个南角台及明确声明的接缝；北墙、北角楼、两侧门洞与门以北墙体保持冻结。

## 5. 后续门槛（按依赖顺序）

1. **先闭合来源接口**：分别注册东/西马道的内转、外折、回程端点和平台边界；把源墙共边连到实际有 owner 的台体/阶面，而不是只比两个 JSON 节点。各段长度口径、宽度、高程和历史/现状差异分别记录。
2. **建立真实联合体**：午门新主台、长翼支承、三直两折五洞、两侧马道、南墙/角台连接一起验证。不能用实心 OSM 全轮廓挤出封住五洞，不能加隐形桥；缺资料处保持 UNKNOWN。
3. **角楼独立配准**：确认两个木构 reference 的构件层级，检查保留角楼最低承重点而非整个屋面 AABB；屋檐悬挑与柱脚悬空不可混为一谈。保留旧 roof 形体不等于角楼形制通过。
4. **几何/材质接缝**：内部重面、重叠台面、法线/UV 相位、墙身收分、墙帽/垛口裁切与边缘余量；现4体各自闭合检查继续保留，新整体另验。不得顺便修改整条远墙的纹理相位。
5. **再注册物理与行为**：实际 collider/walkable 对应真实面、唯一 owner；维持既有非走墙政策，不能仅因三角顶面存在就开放走墙。五门、两马道往返、柱侧/檐下/转角、高落、10/60 Hz 走跑跳，以及移除必要实面必失效的负测试。
6. **近景与最终运行**：先出相同视口的东/西墙—马道及墙—角台近景，不改相机掩盖间隙；再进行全 World 非目标多重集、路线/水域/地图/NPC 回归和真实桌面/手机 GPU。当前审查没有运行这些大场景测试。
