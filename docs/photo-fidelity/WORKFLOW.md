# 逐对象执行门槛

1. SOURCE：看实际图片/页/全景，记录主体、方向、覆盖、日期、现存陈列/历史版本；入口≠室内，缩略图≠360。来源等级和实际查看分开。
2. MODEL：在实际游戏定位同实体/房间，保存前图和相机位置、朝向、FOV、画质、光照。代码存在≠实景出现。无浏览器如实记录；可逆且不依赖实机判断的改动仍做。
3. DIFF：每条写参考可见→当前实际→改哪里→如何验证；屋脊/檐口/柱心/台角控制点先匹配透视。单图看不见的背面不能变通过。
4. IMPLEMENT：先体量/关系/构造，后固定装修、家具、材料。已有测量值不被照片拟合覆盖。未知房间不复制其他宫殿家具；镜面/通景画不是可进入的房间。临时关闭与物理洞口分别处理。
5. CHECK：同相机源/前/后三联，绑commit或HEAD+patch/file hash，逐必需差异闭合。建筑空间、层数、开间、台阶/门窗、家具类别数量朝向、固定装修均独立核。无实机只VERIFY_PENDING；CPU预览、单元测试或整图相似度不能变ACCEPTED。
6. RECORD：保留每特征通过/未知，父总项只汇总；只有完整内/外范围各自闭合才更新既有accepted。状态枚举见QUEUE。全部数据自动统计，读来源数≠建筑完工数。
7. CONTINUE：每3–5可验收工作项集成，主动下一批。缺图只挂该特征、缺实机只挂验证，仍做其他可逆差异。每轮扫全部unfinished，已查缺图入口保存重试条件，不无意义重复查。出现平台真限制先写RESUME；不能以“还有图没看”停全部队列。

## 内陈逐件清单
每房主要物件记录roomId、位置/柱间、类别、可见数量、面向、相对高度/边界、外形来源、原位来源、陈列年代、固定连接、碰撞/通行影响。分别列缺总览、缺侧向、缺背面、缺日期。

## 原功能护栏
地图拖动/地点介绍、寻宝、日夜、直升机驾驶/着陆/下机/回位、108人物/24路线及人物开关、已核验通行、资源生命周期保留。共享kit/碰撞/楼梯修改协调单owner。禁止夹入无关重写、覆盖他人工作树、改权限凭据或main。远端授权与生产发布由owner沿已有规则处理。

## 队列存储与续作

`QUEUE.json` 是唯一权威入口，现为带版本和 SHA-256 的压缩分片索引，不是可直接编辑的任务对象。所有读取、写入、校验统一使用 [QUEUE-STORAGE.md](QUEUE-STORAGE.md) 的公共 API；原始 JSON 只可明确导出到非 canonical 路径。更新先验证所有分片和进度门槛，再原子替换索引，保留旧版本供回滚。此存储变化不改变任务字段、验收状态或运行时输入。
