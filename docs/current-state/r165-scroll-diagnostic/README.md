# Instrumented scroll diagnosis

This branch adds a read-only diagnostic workflow to public product commit fcbec82d237434477750dc61e7d21dc015d18bdc (tree 5915305bd6fd67230731cef35739cb04e436313c). Its only parent is e1287435158ee5aa98e0a1a370cae97021a5c385. No existing product, test, dependency declaration, workflow or runtime file is changed. All 993 runtime files and all seven critical source inputs are checked, alongside the complete original input inventory and added tools.

This is not release acceptance. It does not run the 33-command product validation, World, region builders or production build. A diagnostic-complete exit means that the original scroll assertion's result, observations, identities and cleanup were preserved. A failing primary assertion remains `primaryContract: failed`, even when the optional control passes. `releaseAcceptance` is always false.

The sole primary context uses the real shared fixture at 1280 × 900. The original keyboard English selection, map opening, empty search, focus with preventScroll, scrollTop = 80 baseline, two-frame locale settlement and exact scroll/query/focus comparison remain. A scalar snapshot immediately before and after setLocale uses the same synchronous evaluate call. After the two frames, original comparison values are frozen before detailed geometry is read. Records are published atomically before the original comparison is applied. Instrumentation can affect timing; this is not a zero-disturbance claim.

A second serial context is allowed only for a pure scroll mismatch, without earlier baseline drift, query/focus changes, console errors, unknown ranges, clamping or changing font/document readiness. The original scroll value must remain representable in the new range. Its only product DOM override is `overflow-anchor: none` on the directory. There is no third attempt or restoration of the baseline.

Four fixed endpoint image names are allowed: primary-endpoint.png, primary-directory-endpoint.png, control-endpoint.png and control-directory-endpoint.png. Each pair is captured after that case's values and assertion verdict are fixed. These are not before/after comparison images. Control files are absent when control is not admitted.

The browser deadline is 90 seconds, including launch and context cleanup. An in-process deadline closes the browser; the unchanged identity-bound process-tree monitor still enforces its 240-second outer command deadline. Neither deadline is a kernel hard real-time guarantee. The same sandbox and fixed aggregate RSS limit of 2 GiB apply, with host RAM ≥ 8 GiB, effective admission headroom ≥ 6 GiB and a 2 GiB running pressure floor. These are RAM checks, not disk checks. The existing 128 MiB receipts-plus-scratch polling budget remains. Diagnostic records are limited to 512 KiB each, the command log to 64 KiB, and collected diagnostic artifacts to 8 MiB. A cap, missing receipt, mismatched identity, unknown artifact or incomplete cleanup fails closed.

The existing native Ubuntu 24.04, exact Node/npm/Playwright/Vite pins and actual same-run Chrome binary/package/image receipt are retained. Chrome arguments are checked with the same sandbox oracle. Process-role observations are only bounded diagnostic hints; no missing `--type` token is proof of a specific Chrome subprocess role. No arbitrary environment, credentials or page content outside the fixed directory observations is collected.

The workflow runs exact source validation, locked dependency setup, unchanged UI safety contracts, added diagnostic contracts, the existing toolchain preflight, one diagnostic monitor invocation, fixed-file collection and checksums. No Pages deployment or write permission is granted.
