# Bounded actual single-hall validation

This candidate runs exactly one normal Da Fo Tang host followed by the tool's fault-injected rollback host after reference release. It is not a World, two-hall baseline, UI, build, cumulative CI, or release acceptance. Those activities are NOT_RUN here. Releasing references does not guarantee immediate garbage collection or sufficient memory.

The only public parent is 3dfe70e3869ede71a04f3a85e3106758ca22569c. The approved 18 product changes reconstruct product projection 5eb7fa90f5f4e88809eba55cc0febd790319222a. A private preparation commit is a label only, never a Git dependency. The event identity, product projection, and actual source fingerprint are checked separately.

The original v3 roles, trace schema and 50 route/control scenarios remain. Relative to ownerfix, eight of the eleven v3 files remain exact; host-check, proofs and the related proof test change, with two new bounded retained-surface oracle/test modules. The earlier compact OWNERS encoding remains unchanged. TOOLS.json names these semantic changes explicitly, not as a zero-byte reuse. Every prior gate must pass; failures remain failures with no resource escalation or automatic retry.

The whole checkout Git inventory is compared against the public parent, exact product changes, and new CI paths before, immediately before product import, and after execution. The complete physical INPUTS list includes all 996 runtime inputs and the actual helper/tool closure. Each source receipt keeps that entire physical file list within 512 KiB. Full Git inventory rows are independently reconstructed and checked, then represented by their canonical digest and count. INPUTS and its workflow use explicit two-file self binding; neither is silently omitted from the Git gate.

DEPENDENCIES.json freezes all files in three 0.162.0, @napi-rs/canvas 0.1.100 and its single linux-x64-gnu 0.1.100 native package. The toolchain receipt is a digest/count of a fresh complete enumeration against that lock, not a substitute for the full check. Bare three and explicit product three resolve to the same module. Native loading is checked before product imports; loader/native fallback environment overrides are rejected. Node 24.22.1, npm 11.9.0 and the original lock are pinned.

Fixed limits: Node heap 512 MiB and semispace 16 MiB; complete owned-tree aggregate RSS polling threshold 768 MiB; actual command 90 seconds; outer monitor step 240 seconds. Initial and second live admission require host RAM at least 8 GiB and effective available memory at least 6 GiB. The running floor is 2 GiB. Original v2 namespace/ancestor/limit/OOM/identity/read/gap guards and PID/starttime/pidfd cleanup remain. Polling is not a hard kernel cap; transient overshoot and unreadable/absent process observations are not mislabeled as stronger guarantees.

The run-exclusive root is RUNNER_TEMP/dh-run-attempt with receipts and scratch. Only host-check creates the initially absent tool directory. Tool evidence is bounded to 28 MiB, metadata plus scratch to 4 MiB, and total to 32 MiB. All atomic pending files count in the same budgets while both versions coexist. Complete log is at most 512 KiB. Oversized source, monitor or pending data fails rather than truncating a successful record.

A successful host requires 50 complete trace files plus RESULT, OWNERS and TRACE-SCHEMA. The optional FIRST-FAILED-OBSERVATION is failure-only. The verifier replays every frame, original route/end-pose and controlled-landing obligations, owner/source links, merge/fault/cleanup phases, source identity and complete resource samples. A PASS string or array length alone is not acceptance. Natural contact remains NOT_EXERCISED unless its original observation says otherwise; controlled descent is not natural reachability.

Collection is acyclic: seal payload, write COLLECTION without a self hash, write CHECKSUMS for payload and COLLECTION but not itself, verify the fixed ordinary-file identity table, upload only those files, then compare inode/SHA read-only in a separate 60-second step. Unknown/symlink/scratch/pending entries never enter upload. Collection failures retain safely readable allowed prefixes without turning a failed host into success. Post-upload local verification is not a claim that the server artifact has been downloaded.

All steps are serial. Their maximum sum is 30 minutes within a 35-minute job. Existing workflows are unchanged and do not match the dedicated branch. Final actual execution requires review of this complete candidate and a single authorized remote event.

The frozen pure selections are 42 v3 Node cases (33 retained registrations and nine new bounded surface contracts), 56 adapter Node cases, and 59 Python monitor cases (42 original process/resource cases, seven atomic-publication cases, eight wrapper-clock cases, and two compile-cache environment cases). Synthetic full receipts do not prove actual hall geometry or physics. The adapter accepts an unmarked post-merge visible owner only when it is the exact owner of the final after-real-merge ray; it cannot stand in for any of the 294 original component meshes or a trace owner. Complete failure prefixes remain failures.

Incomplete failure prefixes are not complete acceptance. The original MemoryWatch sampling/pressure/PID core is unchanged.
