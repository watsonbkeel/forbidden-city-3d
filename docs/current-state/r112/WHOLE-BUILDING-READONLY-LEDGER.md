## 决策摘要

**并非“只有两条柱联可做，其余都缺资料”。**目前可明确转实施设计的高影响组合至少有：

1. **乾清正面到达组合：前月台4座鎏金炉＋三组正门每组4扇的实际门叶关系**。两项均有官方照片与真实源码差异；保留中央丹陛、甬路、既有低台和通行，不复制官网临时围栏/闭门状态。龟鹤、日晷嘉量在同一月台完整清单里继续定位，不因先做4炉而删掉。
2. **乾清中央室与交泰中央陈列的完整同机位核位/主视觉改进**：官方中央照片不是缺源，现有五屏三阶/钟漏/罩列也不是未实现。应先扣除既有实作，再针对图证覆盖的屏框、主要轮廓、内檐/藻井色区与相对比例立实际 RED，不能因为未找到全文而把整个交泰内景停掉。需要配准不是来源阻塞。
3. 乾清前柱联可随中央空间组实现，但不能盖过上述两组；后副联、交泰铭文的具体阻塞保持局部，不传染到全部内外景。

**没有本轮新构建/同机位证据的“疑似比例问题”只列待核，不能先宣称已找到几米偏差。**旧 R61 CPU 图是历史诊断，不能当 R110 纹理全部加载后的实机结果；R102 黄罩/毯已采用，不再重复改纯色。

### 怎么绑到现模型，而不是随便放4件

- `PalaceBuilder.buildComplex` 的后三宫 `rects[0]` 与 `top` 是月台来源；当前 nominal terraceY=2，**不得直接假设真实渲染表面精确2.0**。`buildTerraceUnion` deck厚.1、中心y1-.03，其可见顶面与登记walkable有细微差；落脚先取本次真实Float32面，不能插入石板或悬空。
- 4炉位置需要同一正面及斜面定性匹配，并记录可逆拟合。不要将图像 x 比例直接换算成确定米数；不得沿三台参数复制 `terraceOrnaments` 的整套日晷/龟鹤。
- **现源柱列不是均匀6.5m网格**：`QianqingFrontageGrid.fittedStations` 为 `[-23,-18,-13,-8,-3.25,3.25,8,13,18,23]`。正面图的内对炉投影落在每侧3.25↔8柱间、偏8柱；外对落在13↔18柱间、偏18柱。拟 `X=±6.5/±16.2` 保持此拓扑，可作首轮工程候选，外对也可在同一柱间向外微调后比较；不能宣称这就是实测坐标。
- 前柱当前 `Z=316.8−12.5=304.3`；第一 terrace rect 前缘 `Z=304.3−6=298.3`（石板外挑与台阶外缘另算），不是约296的整个台阶外缘。拟 `Z=300` 在矩形前缘后1.7m、前柱前4.3m，是有可行空间的初拟；应再核该线真实栏杆、丹陛开口、炉体支座净空以及同图前后关系，不能仅凭本段计算宣布配准通过。
- 保留中央丹陛上口、前廊通行、两端穿堂接近路线、柱脚/门扇扫掠净空。共享可见炉模板；每实例用独立身份和真实支座/紧贴体几何碰撞。低LOD保留4个主要轮廓，不把远处变为0件。
- 归后三宫常驻外部所有权，既不能归 Qianqing 室内S，也不能在角色资源驻留中创建。dispose/重复构建需要恰一次生命周期检查。
- 龟鹤、日晷嘉量、石亭、台下缸各列自己状态；没有在3张图中闭合身份/落位就写待定位，而不是把它们统称已做“全部月台陈设”。
