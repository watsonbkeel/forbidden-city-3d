# V6 坤宁宫：入口与虚拟通路

基于已发布 V5 `ea35d55ebcdb98b271109b80f38b3acb8da052f7`。
本说明是结构和导航实现记录；最终浏览器、性能与发布状态另列于 V6 验收记录。

## 怎么找到入口

地图点击“坤宁宫”后，落在原台明中央台阶下的共享台面 `(0,371)`，逻辑脚高为5m；这不是院落地面，更不是通过传送证明已经爬上台阶。视线朝向偏东的真实门位 `(-5.111111,378.6)`。

沿保留的中央石阶上台，继续到南廊。面对坤宁宫正面，向右（东）走到匾额旁紧邻的一间，从木板门进入。中心匾额下方是窗，不再是通行洞。退出时原路从南门回廊；若要向御花园走，沿南廊到东端或西端穿廊，再从北廊走回原有后阶。北面中间也没有本版虚构的门。

这是模型中的可行走路径，不代表博物院当天准许游客进入。内部暖阁和库房的准确分隔门位缺证，本版不添加推测内门，也不提供两处室内步行路线；这不表示历史上分隔完全封死。

## 一个共享坐标来源

`data/architecture/kunning.json` 的具名点和通路同时供建筑、家具避让、地图传送及路线验收使用。保留原运行锚点x0、z386.1、朝南和共用台明；门位、廊深、开口宽等属于明示的模型拟合值，不是现场实测。

传送只使用中央阶口的具名起点，不从旧中门中心或任意横移搜索另一个“能走进去”的洞。落点安全检查沿原阶、南廊转弯、偏东门外与门内逐段用真实碰撞和可行走面探测；缺坡面、过大托升、身体阻挡或终点标高不符均拒绝。建筑地理中心仍供地图与分区加载使用，镜头朝向与入口平面另取真实偏东门位。

只有两条原固定路线改变：
- “乾清宫→交泰殿→坤宁宫”：前面的乾清宫/交泰殿点序列逐字保留，末段接中央阶口→南廊→偏东门内。
- “坤宁宫→御花园→神武门”：从同一门内点原路退出，经东端穿廊、北廊和原后阶，接回完全相同的御花园/神武门后缀。

其余31条固定路线、原56条自动路线和V5两条侧阶自动路线不变。`tests/fixtures/v5-fixed-routes.json`保留原33条完整点序列。旧中轴前门、旧中轴后门与x4.7旧后出意图另作必须被实体墙窗挡住的负例，不能删除旧错误后把新路线的通过当作全部证据。原固定路线仍使用原执行器；本轮真实控制器专项另用具名途经点跨越诊断，不改变原门禁容差。

## 检查范围与运动边界

导航测试先在原V5行为上得到三项实际语义失败：目标还指向中心、落点不消费共享阶口、受阻后会横移搜索。首次启动另有继承JSON导入兼容错误，单独保留，不能算作这三个功能红例。

随后8项导航检查验证真实B世界的阶口支持与完整门内安全路径、缺失原南坡面的拒绝、真实入口被封时拒绝、两条改动路线的精确边界。几何/生命周期中的固定速度CollisionManager步进与真实FirstPersonControls矩阵分开计数。

`tests/kunning-controller.test.mjs`另用真实FirstPersonControls测试入口往返、东西端穿廊往返，60/10Hz、慢走/快走、前进/后退，共24种。初始高度明确为原共享台面5m，禁用箱体救援托升；DOM、时钟和朝向由测试控制，不是完全手动浏览器游览。快走在拐角/终点前减速，不声称每段均达到恒定最高速度。

不能把逻辑支持或几何平面对齐当成镜头脚面逐帧接地：
- 原控制器上坡时对镜头脚面做指数平滑，地面身体碰撞则用`max(feetY,groundY)`。目前记录到上坡镜头脚面比逻辑地面低0.444118m，下坡又可暂时高于地面1.43m。
- 10Hz慢走在北端401m回转时，惯性曾越到401.35m，进入原来就存在的后方下阶（z401.1→409.1，高5→0）；该处真实逻辑地面约4.8439m、镜头脚面约4.9434m。V5原世界同坐标查询逐值相同。新增测试起初错误地要求全程脚高≥5，修正这一假设后保留原红例和全部帧记录，并未改动生产物理、坡面或旧门禁容差。
- 专项仍要求完整途经点跨越、实际支持不掉到地面0、镜头跟随滞后不超过原STEP_UP=.6范围、经过台明高度且最后回到5m落稳。这是诊断边界，不是古建工程安全或人物全程贴地认证。

最终还需冻结源码上的实际浏览器入口、B/S与失败回退、原始整组回归及六机位性能。神武门原11m/5m差异继续保留。
