# R18 Baohe column identity candidate

Base: R17 local311ac549779654620b85284749d5201337dd9d4d, remote0075f9482e07d7c017d0a6f7168c88feca3f1b20, treeea543a78c25dcb7906fcb8638019c4290080ab94. No public deployment is part of this candidate handoff.

## Evidence and visible defect
The Palace Museum building page describes five depth bays and omission of six front inner columns. Its1941plan is oriented south at image top and north at bottom. The middle six stations in the front inner row are absent; the rear middle posts exist. The previous generic model did the opposite: all six front posts present, rear middle two omitted for a throne shortcut.

The museum-contributed interior photograph shows red inner posts. Architectural terminology金柱 names an inner structural column; it does not itself mean a gilded finish. The generic model erroneously used a gold material on some Baohe inner posts. Photo capture date is unverified, so this is source-supported appearance registration, not a2026condition survey.

## Bounded implementation
Only Baohe's post-presence/material rule changes. Front inner row indices2–7 are omitted, rear indices4–5 are restored, and all columns use the existing red wood material. Each present post and its collider are generated together. No invisible collision is left at an omitted post. The R17plinth, four north walking strips, door openings, frontage stations, roof, throne and other halls remain byte-exact.

The resulting34posts are a model count, not a historical surveyed total. Current four depth stations remain inherited; the drawing has six station lines. Do not change to six equally spaced rows or stretch the drawing to the outer envelope. Full depth registration, front veranda/door setback, differing diameters and the rear throne relationship remain separate work. The restored centre posts lie within the existing solid throne footprint; that footprint is not expanded or opened to fabricate a route.

## Acceptance
Focused tests require exact40station identity,34geometry/collider pairs, six empty front sites, both rear centre posts, red material and exact retained noncolumn geometry/navigation. A real CollisionManager cross-aisle must pass in both directions; retained rear columns must still block. Compare entrance and side views against unchangedR17 with the same camera/noon/FOV. Perform native approach/cross-aisle movement and unchanged necessary route/performance gates before a handoff. No real-phone claim.
