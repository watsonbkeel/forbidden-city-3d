## 依据与范围

见[昭德门证据卡](cards/zhaode-gate.md)。本轮只修正一座门的高台、三间门身加周围廊、单一中门和南北慢道关系，以及两个必须封闭的相邻接头。保持原模型锚点，不改变贞度门、主殿、坤宁宫或神武门位置。

文献转换的建筑尺度与历史平面读数不完全相符，两套证据各自保留。台基外包、坡宽、逐间尺寸、门线、前后分配和北立面细节仍是暂定模型，不是测绘认证；游戏通行不代表当前开放。

## 唯一轮廓与常驻建筑

采用独立 `zhaodeGateGeometry(item)`，显式选择 `gateProfile: zhaode` 和 `gateKind: three-bay`，不得落入 V3 五间三门模板或按宽度猜类型。有限坐标、正交朝向、尺寸与拓扑需在生成前验证。

常驻 B 层拥有门体、双扇门、闭合台基、南北石慢道、栏杆、封闭接头、碰撞和支持。无需 S 家具层。可见三角形、碰撞、支持、地图几何与路线接触点均来自同一个 profile，南北坡分别定义，不能复制单侧数值冒充实测。

高台禁用 box rescue，不能从地面靠近侧墙就被吸上台。慢道采用与可见楔体相符的连续斜面支持和楔体内部切片碰撞，不使用覆盖整坡的高碰撞盒。身体碰撞、逻辑支持高度、平滑镜头脚高分别记录，完成路线不代表每帧贴地。

## 两处封闭接头

墙洞与两条直接相邻庑房内端从同一门轮廓取得坐标，不在 JSON 与代码维护两套独立数字。仅缩短靠门端，保留各条外端、地坪、屋顶级别与方向，端部对高台保持封闭。现有庑房与高台不等高，不暗造侧向通路。

缩短既有通用庑房可能重排该整条的柱间与家具，故这两条作为明确允许变化的对象整体对照；其余十四条庑房和原四座专用侧门必须独立保持不变。封闭端面与高处碰撞需要覆盖门台上的身体，不能用从地面起仅三米高的旧墙碰撞冒充足够的高台围护。

## 围护与材质接合

凹入的南北侧间墙延伸到既有门楣顶标高，避免墙上方留下无依据的漏天空缝。这是保守的工程封口，不是对历史墙头细部的新认定。砖石台身与0.08m铺石顶层组成相邻闭合体，接头红墙从台面起、顶面仍为7m；原台基外包和高程不变，低处由闭合砌体围护，避免红墙与砖墙表面重合闪烁。坡道侧面使用按面方向展开的石材UV，不能将固定X的侧面压成一条纹理线。

## 路线与验收约束

- 保存 V6 的33条固定及58条自动路线原名和逐点序列，只新增一条昭德门往返路线。
- 使用实际 FirstPersonControls 与 CollisionManager，从坡脚外地面开始，验证实际选中的南坡、台面、北坡支持；按60/10Hz、慢走/快走、正走/倒走和双向分开记录。
- 删除或移位每一条慢道必须令支持断言失败，即使某个 XY 终点偶然到达。侧面、栏杆、柱、关闭门扇、封闭接头及台基内部不可成为捷径。
- 测试辅助朝向、固定时步与正常应用 RAF 下真实键盘/触摸输入分开说明，不宣称未辅助的人工作业或真实手机测试。
- 五张普通透视与一张真实正投影俯视固定机位复用 V6 基线；正投影诊断的相机和渲染路径另记，不把其渲染统计作第一人称性能。
- 原八项门禁和六机位各60帧预算保持。神武门原11m/5m失败单列；新增失败不得藏在继承红项下。生产包需实际运行并与独立重建逐字节核对。
