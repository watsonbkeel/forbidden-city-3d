# R3 V2：保留结构的材质合批验收

日期：2026-10-14 UTC。基于已发布 V1 `e9d91cd721b510052397eb396b0e19562dd71763`，新分支 `feat/r3-v2-material-batching`。体验方式见 [TRY-V2.md](TRY-V2.md)。[V1记录](ACCEPTANCE.md)保留为历史证据，不覆盖其当时失败的性能预算。

## 变化边界

本轮只把乾清门六种已有纯色材质合为一次提交，不增删结构、门道、影壁、台阶、甬路或碰撞。原14,160个三角面全部保留，4,800个参与合批的三角面逐顶点保留位置/法线/UV、线性颜色和粗糙度；真实门体网格24→19，162个碰撞体与6个可走面不变。

有贴图的瓦面、门扇、台阶及其他建筑材质均不改。全局合并器、移动控制、原测试预算与基线未改。详细实现/资源归属见 [V2-MATERIAL-BATCHING.md](V2-MATERIAL-BATCHING.md)。四座建筑的证据与近似尺寸仍见V1各[建筑卡](cards/)，这次性能改善不增加任何实景核准对象。

## 已核实结果

- 当前结构/合批专项66/66；全部新增Node测试含跨平台、边界、纯Node场景构建共74/74。
- 独立审查确认真实门体全部几何属性、碰撞、可走面和未选网格保持；新旧资源正常释放。两项通用输入边界已补防护：自定义阴影回调、冻结世界矩阵必须拒绝，并验证失败不改对象、不释放源资源。
- 浏览器高→低→高画质在午门及乾清门三个机位正常，未发现pageerror、console/WebGL错误、HTTP失败；45个纹理响应成功。
- 原完整浏览器回归24/24；固定步行132/132；自动路线155/156，失败仍是V1记录的浴德堂慢走路线，没有新增跳过。
- 九组1600×1000同机位图逐像素比较：最大仅0.00406%的像素超过24级通道差阈值。乾清门正/斜/后甬路分别65/55/33个像素超阈值，平均通道差0.0608/0.0289/0.0303（0–255）。任意微小RGB差分别约4.98%/3.23%/3.93%，因此不能声称逐像素完全相同。实际查看轮廓、三阶、影壁和甬路，未见结构改变。

## 性能与生产包

原六机位、每点60帧测量完成，calls/triangles全部通过仓库原10%预算。没有改`tests/perf-p2.json`，没有放宽阈值；软件渲染fps仍有6条警告。

六机位提交三角面数与V1逐点相同，60帧计数范围稳定，资源/控制台错误0。另在交泰殿的对照截图机位，合并后的较大包围盒会多提交一部分三角面（两次渲染累计3,552面），这是剔除粒度变化，不是新增模型；正式六机位预算仍全部通过。

最终生产包 `index-kFP-Xyym.js` 与独立重建产物逐字节一致。桌面高画质与手机低画质均确认新合批着色器实际编译成功，45/45纹理响应成功，编译/链接/WebGL/页面/控制台/请求错误均为0；地图、8个快速目的地与键盘传送可用。生产环境不暴露开发调试接口。

短验另发现继承的手机画质标签缺陷：实际初始低画质渲染，但设置按钮仍显示“高画质”；本轮未改移动端初始化/设置菜单，失败记录保留。整体`test:gate --keep-going`仍因神武门锚点和浴德堂路线两项继承问题退出失败，不能把性能通过写成全门禁通过。

## 仍然保留的限制

神武门锚点11m差异、外西路浴德堂自动慢走路线失败，以及V1列出的未核实比例、装饰、全宫其他建筑和当日开放范围均未由本轮解决。软件渲染fps不能当成用户桌面/手机性能承诺。
