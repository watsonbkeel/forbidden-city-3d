# R97 性能候选评估：不纳入生产

基线为已交付R96 local `f025c09c` / remote `f0603a98`。本轮完成三个候选的验证，但不将内部调用减少冒称实际体验加速；最终运行源码恢复精确R96，版本身份仍R96，不发布无收益的性能改动。

## 等价结果
- 每manager帧投影/视锥复用：真实2角色frustum调用2→1、空帧0；独立16000投影、108×200 manager状态逐值等R96。
- 静态实例矩阵/包围盒跳更新：发现并修复count缩少时basis变化导致尾slot恢复旧矩阵的真实缓存缺口，保留RED。修后独立600序列与两实际world800帧实例、矩阵/bounds、身体输出精确相同。
- 外脚行memo：300→100扫描、最大重复5→1，全几何/碰撞/profile6项等价。但实际Garden五配对build中位仅−1.13ms，噪声达±75ms且首对冷热不平衡，拒绝。历史Garden约+182ms总重建回退未解决。

## 成本结果与决定
- 储秀low实际2角色steady五对p95增量中位+0.022ms（范围−.364～+.105）；无可信整体收益。
- 人物cold协议与R96完全相同：10个全新Node、5交替对、固定world构建后人物cold、600模拟帧、low/30Hz，全部样本保留。后妃R96首显113/90/110/90/99→候选107/108/111/95/108，中位99→108，差−6/+18/+1/+5/+9。不是实机秒数，但不支持首显改善。
- 24实例真实Renderer微测：static p95约.020–.030→.011–.017ms，矩阵版本1800→1；moving矩阵版本均1800，成本有涨有跌。微测静态省时不能抵消实际世界的整体回退，不能当GPU/FPS成绩。
- 最后实际太和low机位原拟密集检查，但实际仅3个可见实例，应明确不称高密度证据；此场景whole-update p95五对均回退约+.010～+.181ms。没有追加相机/样本直到找到有利数字。

结论：恢复`CharacterLOD.js`、`CharacterManager.js`、`CharacterRenderer.js`及`DuixiuOuterRock.js`为R96精确字节。保留全部实验提交、源归档、RED/GREEN、原成本数据；不加缺乏实际证据的高密度阈值特判、不提高预算/降低模拟频率。不称R97性能需求已全部完成；剩余性能问题继续台账，下一已批准R98形体任务不重复本轮失败优化。

实验测试/便携旧源在Git实验提交中保留，当前归档`reports/r97-performance/rejected-*`是原相对路径的源材料，不作为当前产品测试入口。重新评估应在隔离实验提交运行，而非把优化计数断言套回未优化R96。
