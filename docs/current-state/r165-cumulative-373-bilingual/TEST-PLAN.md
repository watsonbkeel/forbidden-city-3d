## Live UI memory admission

The UI-only aggregate RSS threshold is 2,147,483,648 bytes (2048 MiB). The production build's 768 MiB V8 old-space setting is unchanged. The threshold is a sampled stop condition, not a kernel hard cap or a guarantee that full UI validation will fit. Earlier 905.63 and 912.43 MiB startup peaks had no completed browser launch. A later launch completed before a 1552.449 MiB aggregate peak stopped its 1536 MiB window; no full layout completed. That run observed at least 13.977 GiB effective headroom and unchanged OOM counters. The fixed 2048 MiB window is about 31.9% above that sampled peak, not a guarantee of completion.

Before the UI command starts and again immediately before Chromium launch, actual MemTotal must be at least 8 GiB and effective available memory at least 6 GiB. Effective available memory is the minimum of /proc/meminfo MemAvailable and every finite ancestor memory.max minus memory.current and memory.high minus memory.current. The high value is conservatively treated as a pressure boundary. Disk capacity and nominal runner specifications are not memory evidence. The immediate prelaunch receipt binds the same event SHA, run, attempt, repository and ref as all other receipts.

This reader supports native Linux unified cgroup v2 only. It requires the current process's namespace link and inode to identify Linux's reserved initial cgroup namespace, 4026531835, plus exactly one cgroup2 mount exposing root '/'. This is an explicit compatibility requirement, not a claim of portability to arbitrary kernels or containers. Legacy, hybrid, nested/unknown namespaces, hidden ancestors, threaded domains, missing controllers or files, denied reads and malformed values fail closed. There is no host-only fallback.

Only that proven hierarchy root may omit all five non-root files: cgroup.type and memory.current/high/max/events. It is recorded as root-not-applicable, not an invented unlimited limit. All non-root ancestors through the actual membership leaf require readable domain type, current usage, max/high values and OOM counters. The walk is bounded to 32 nodes. Finite limits remain lossless decimal strings. Linux documents the non-root interfaces in [cgroup-v2.rst](https://github.com/torvalds/linux/blob/master/Documentation/admin-guide/cgroup-v2.rst); the reserved namespace identity is defined in [nsfs.h](https://github.com/torvalds/linux/blob/master/include/uapi/linux/nsfs.h) and used by the [cgroup namespace initialization](https://github.com/torvalds/linux/blob/master/kernel/cgroup/cgroup.c). Unsupported or changed root semantics require a new review rather than an unlimited-memory assumption.

During the UI command, bounded direct reads run on a 0.25-second cadence, with at most a 1-second completed-observation gap and a 1-second measured read duration. Read duration is checked after the read returns; it is not a kernel syscall deadline. Effective headroom below 2 GiB, a changed limit/topology/inode/device, an OOM counter change, process cgroup migration, unreadable data, delayed reads or exhausted sampling bounds fail through the existing PID/starttime/pidfd cleanup. The fixed limits are 1024 memory observations and 64 owned processes per membership check. No subprocess is launched per poll.
