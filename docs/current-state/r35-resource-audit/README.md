- 两个检查点分别从精确 Git 提交提取到独立目录，使用同一审计工具和已安装的 Three r162 依赖运行。
- 报告核对 `src/` 与 `data/` 的全部 188 个文件身份；R35 还逐项与集成工作区实际文件复核。六个可选 GLB 另列各自 SHA-256。
- 主比较固定为北京时间 2026-10-20 12:00，即 `2026-10-20T04:00:00.000Z`。另在北京时间 21:00 运行 R35 夜间复核。报告同时保留真实执行环境的主机观察时间，不把预览时刻当成执行时间。

这是 CPU 对象、几何缓存和释放所有权证据，不是 WebGL 分配、真实 GPU 显存、帧率或画面观感验收。

## 本轮修复

1. Three r162 的 `UnrealBloomPass.dispose()` 遗漏其私有 `materialHighPassFilter`。后期处理管线现在在画质重建及完整销毁时补齐释放，不改 Bloom 参数、渲染路径或场景。
2. 九龙壁照片纹理属于单次宁寿宫区域构建，但原来未登记为该区域拥有的纹理。现在登记到 `CourtKit.ownedTextures`。
3. `CourtKit.buildPlaqueAtlas()` 原来的数组赋值会覆盖之前登记的纹理。改为追加，确保九龙壁照片与匾额图集都能释放。

第 3 项是独立复核发现的真实覆盖缺口。最初只构建九龙壁的简化测试不足以覆盖运行中的完整区域，现已替换成全部 50 个项目、30 块匾额的实际宁寿宫配置。完整区域测试在修复图集赋值前明确失败：照片释放次数为 0，预期为 1。四次完整构建、合并、销毁和重建现均验证：

- 照片与图集分别恰好释放一次，重复销毁不再次释放；
- 共享材质与共享纹理不被区域销毁；
- 重建后的几何资源清单、碰撞、可行走面及地图数据一致。

照片文件为 4096 × 380、616,768 字节。该信息用于明确资源范围，不能据此声称实测节省了多少 GPU 显存。
