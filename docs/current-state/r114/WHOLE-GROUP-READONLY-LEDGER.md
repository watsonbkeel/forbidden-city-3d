## 最短实施建议

**首选有来源、能形成空间收益的组合：承乾正殿月台/南中央阶＋主殿侧院间门与短墙＋前院东西三间硬山配殿。** 不要以新增5兽替代这个组合。官网图04一次证出月台、台阶和主殿一侧院间门；正文同时确认两进及前后各两配殿。当前主殿只有四周0.8m窄平台，无独立宽月台，院墙仅外周，前配仍通用悬挑gable。该组至少解决 E1/E2/E5/E6，而不虚构室内。

**后院两配、后殿耳房与西南井亭必须进同一父组清单；本批不能因来源不足而删除。** 已有官方文字能授权“有这些结构”，但本地5张图库没有足够后院侧向/俯视图来确定后配、耳房、井亭的准确体量及相互门路，不能把文字当作随处复制标准房的许可证。若没有时间打开已索引的单个后院全景，应提交这一组 `BLOCKED_SOURCE/待定位`，不是宣称承乾全宫完成。

### 结构组合的实施边界

- **正殿月台**：当前 `RemainingResidentialHalls.js:buildRemainingHall → kit.hall`，其台基仅 `(w+2pad)×(d+2pad)`，没有承乾专属月台。用图04轮廓拟合前伸深度，保留主殿本体及R103南窗；独立可见石材侧壁、顶面与实际碰撞/可走面共同变化。尺寸标 `REVERSIBLE_MODEL_FIT_NOT_SURVEYED`。
- **院间侧门/短墙**：`east-six/8` 仅外圈，整个数据表没有承乾院内横墙/侧门。需新专属绑定，门及墙避免重叠原主殿端墙、外墙和前配北端；“有门洞”要由真实地面走通，不在导航图画线代替通路。
- **前院配殿/11、12**：当前自动算3间，但 `hardGableEnd` 未传入，默认false；母页明确硬山。应两实例专属改，不改全园默认。注意 `ZoneBase` 当前不把item.hardGableEnd透传给params，单在JSON加键不会生效；`EastUnknownAnnexInventory`按冻结声明逐字段校验，也要保持或正式迁移绑定，不能误掉UNKNOWN库存策略。
- **后殿**：五间/硬山/R103四南窗已有，不能重复算新成果。可核图03低前阶/平台；当前ph=.45使kit不生成steps，属于可见前缘差异候选，但图示尺度仍需拟合，且不能越界捆绑为整后殿内景完成。
