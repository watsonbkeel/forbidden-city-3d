## Output accounting and native writes

The Node child may write only stdout/stderr. It streams complete ordered evidence into in-memory SHA256/count receipts and emits one final JSON result on stdout. All production diagnostic logging goes to stderr. No child result, spool, image, temp, heap snapshot or diagnostic report file is permitted.

The parent owns these seven ordinary fixed files under one fresh evidence root: `input-manifest.json`, `admission.json`, `resource-initial-raw.json`, `resource-decisions.jsonl`, `started.json`, `stdout.json`, `stderr.log`. `terminal.json` is the parent's reserved final outcome. Only empty `tmp`, `home`, `cache` directories are allowed. The child environment maps TMP/TEMP/TMPDIR, HOME and XDG_CACHE_HOME to those directories. Unknown files/directories, links, file identity changes or unresolved write reservations fail the audit, even below the size limit.

One ledger reserves positive growth before a durable parent write, checks full identity, writes/fsyncs, then commits the reservation. Failed writes remain charged and cannot yield acceptance. The 16 MiB cap includes all seven files and the 64 KiB terminal reserve. stdout has an additional 1 MiB result cap within the same envelope. stdout and stderr are separate and neither is silently discarded or trimmed to create success.

This is cooperative prewrite accounting, **not kernel filesystem confinement**. Redirecting HOME/TMP/cache does not prevent a native library from writing elsewhere. Its concrete source/config behavior, all native loaders and actual temp/cache expectations must be audited before activation. Any newly needed durable writer must be listed and reviewed in this same envelope, not supplied a separate allowance. Bootstrap/npm/font/browser installation, build outputs and the inherited UI evidence are different pre-existing phases, not claimed to fit this E45 16 MiB phase. Their actual write scopes must remain explicit in the integrated workflow; no unreviewed duplicate repository/dependency provisioning is authorized.

## Proposed resource stops

- Exactly one production child, no retries or automatic limit increases.
- Node old-space 1536 MiB and semi-space 16 MiB. These flags do not bound native allocations.
- 3 GiB sampled process-tree RSS stop at 0.1-second intervals. Direct-child `wait4` peak is recorded as an additional check. Sampling may miss peaks and is not a kernel hard limit.
- 90 seconds from immediately before spawn through child work, TERM/KILL/reap cleanup, final result validation, output audit and terminal persistence. The cleanup interval is reserved within those 90 seconds, not appended. Disk I/O itself is not kernel-time-bounded; observed overruns cannot return PASS.
- The unchanged SHA-pinned R177 reader resolves actual cgroup v1/v2 ancestry, controller quotas, current usage, OOM counters and host memory. Host MemAvailable is not a container quota. Missing or hidden active controls fail closed. A genuinely exempt native v2 root may use its verified host bound; this is not an exemption for an unreadable controller.
- Three fresh samples one second apart, then a fresh complete re-admission after the prelaunch byte audit. Every sample must have unchanged controller identity, capacity/quota and OOM state and sufficient headroom for `3 GiB + max(1 GiB, ceil(capacity/5)) + 256 MiB`. The same reserve and identity/OOM checks continue during execution.
- Cleanup uses a private session, exact PID/start identities and pidfds. Descendants that remain live, unknown RSS, failed identity binding or unverifiable cleanup prevent acceptance. No PID reuse inference is allowed.
- The definitive result is the supervisor's final returned status and nonzero/zero exit, not an earlier persisted PASS snapshot. Final persistence/audit overrun triggers at most one corrective failure receipt. An uncertain corrective write stays `EVIDENCE_UNCERTAIN`.

All capacities are stop proposals for independent audit, not measured eight-zone needs or admission authorization. The whole-eight startup peak remains unknown.
