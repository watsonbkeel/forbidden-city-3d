### PerfHUD 整帧计数说明（P0b/P0c 读数前提）
- 渲染管线是 EffectComposer 多 pass：RenderPass → SSAO → Bloom → OutputPass → FXAA，另有阴影贴图 pass。three r162 在 `autoReset=true` 时每次 `renderer.render()` 开头清零，读到的只是最后一个 pass（FXAA）。
- PerfHUD 构造时设 `renderer.info.autoReset = false`，`update()` 在一帧所有 render 结束后读数再 `info.reset()`，因此 calls/tris 是**整帧合计**（主场景 + 阴影 + SSAO 法线 pass + 后期全屏 quad）。
- 交叉验证（东六宫中点）：单独 `renderer.render` 主场景 = 119 calls / 688,996 tris；整帧 = 256 calls / 1,377,883 tris（≈ 主 pass ×2 + 后期 pass）。
- 实测（DEV，headless）：初始 `display:block` → F3 → `none` → F3 → `block`；面板文本 `FPS 0.9 (15.2 ms) / Calls 466 Tris 1,441,567 / Geom 207 Tex 79 / Zone - / Loaded -`；修改 `__perf()` 返回对象不影响下次读数（只读）。
- `window.__perf()` 在 rAF 回调里调用时（perf.cjs 的做法），主循环 rAF 先注册，读到的是当前帧整帧值。

### 已知问题
1. **东六宫中与宁寿宫两点 calls/tris 完全相同**（256 / 1,377,883）。已核实不是读数 bug：两点朝北时视锥内可见 mesh 数都是 106/212，单独主 pass 也相同（119 / 688,996）；改朝向即不同（东六宫朝南 298 calls，宁寿宫朝西 344 calls）。原因是当前场景大量用合并/实例化大 mesh（总共只有 212 个 mesh），两处朝北看到的是同一批合并块。P0b 拆 zone 后这两点会自然分化。

### 最终接口（Phase 1 依赖）
- **坐标系**：原点 = 太和殿中心，+Z 北，x 负 = 东，单位米，1:1。`LAYOUT`（src/config/constants.js）：`START_POSITION (0,1.7,−470)`、`WUMEN_Z −419.6`、`JINSHUI_RIVER_Z −310.8`、`TAIHE_GATE_Z −214.2`、`TAIHE_Z 0`、`ZHONGHE_Z 65`、`BAOHE_Z 123.2`、`QIANQING_GATE_Z 215.3`、`QIANQING_Z 316.8`、`JIAOTAI_Z 354.1`、`KUNNING_Z 386.1`、`IMPERIAL_GARDEN_Z 470.5`、`SHENWU_Z 531`、`PALACE_RECT {halfX 376.5, minZ −425, maxZ 536}`、`BOUNDARY {x ±400, z −500..560}`。
- **数据**：`data/anchors.json`（name → {kind,x,z,w?,d?,conf,src}）；`data/zones/*.json`（schema 见 data/schema.md；kind = gate / hall / wall / courtWalls / corridor / cityGate / region / nineDragonWall）；**zone 数据只能经 `tools/p0c-relocate.mjs`（OVERRIDES）生成**，P1-Z 接手后可改为直接编辑 JSON 并废弃脚本（需在任务卡中明确切换点）。
- **ZoneManager**：`register(json, Builder?)`、`init(scene, library, collisionManager, initialPos)`、`update(playerPos)`、`ensureLoadedAt(x,z)`、`findZone(x,z)`、`getLoadedIds()`、`getCurrentId()`、`getRegions()`、`getMapItems()`、`getRooms()`、`onLoad/onUnload` 回调、`buildTimes`、`dispose()`。
- **ZoneBase**：`constructor(library, zoneJson)`、`build()`（返回 group/colliders/walkables/regions/mapItems/rooms）、`update(dt)`、`dispose()`；子类可覆盖 `buildHall/buildGate/...` 定制区内建筑。
- **CollisionManager**：`addColliders(list, tag?)`、`addWalkables(list, tag?)`、`removeByTag(tag)`。
- **性能读数**：`window.__perf()`（DEV）→ `{frame, frameMs, fps, calls, tris, geometries, textures, …}` 整帧值（PerfHUD.snapshot 副本）；PerfHUD `zoneProvider`。
- **门禁**：`test:zones` / `test:anchors` / `test:smoke` / `test:regression` / `test:walk` / `test:perf`（浏览器类经 run-with-vite）；`test:zone-equiv` 已退役（P0c 坐标迁移后旧 SideCourts 不再等价，SideCourts.js 保留未删）。

### 遗留问题（按归属）
**P1-R 渲染性能**
1. calls 比 P0a 高 30–55%（P0b 起分区按材质合并批次 ×7）：BatchedMesh / 跨区材质合批。
2. 御花园点 tris +57%（vs P0b）：花园甬路/花坛/树木 LOD、邻区（东/西六宫）在园内被园墙遮挡时降级。
3. 单区构建 >8 ms（`CourtKit.finish()` 不可切片，axis-courts ~50 ms 一帧卡顿）：拆两段分帧或 Worker 预合并。
4. silhouette 未实现：远区卸载后整片消失，1:1 尺度从午门外望北端尤其明显。
