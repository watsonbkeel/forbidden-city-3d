## 已实现的工程接口

`src/scene/characters/` 包含程序化七身份 Kit、统一 CPU/GLSL 动作方程、有上限共享资源池、真实 InstancedMesh 批次、逻辑 Manager、LOD/预算、只读 WorldAdapter、按弧长编队巡行、统一候礼阶段、配置 schema 与集成 System。

- 七模板为皇帝、朝服官员、礼仪执事、妃嫔、宫女、太监、守卫。均为匿名清代主题演绎，不声称具体官阶、具名住户或精确还原制服。
- 米制、人物不缩小配建筑。只读真实地面/平台、座面与鞋底接触。缺支承保持 pending/error，不回退世界原点、地面零值或屋顶最高值。
- 太和真实 B 回退和 S 内景 20 轮切换/恢复已做几何与生命周期测试，支承数字通过不等于坐姿视觉通过。
- 两条已核验的同区路线使用全段半径扫掠和 ≤0.25m 采样，三人队列共享时钟及固定弧长次序，端点共同停顿和转向。未启用城墙巡行或跨区巡行。
- 日夜使用既有 daylight，不改系统时间；值守保留，日间演绎人物在夜间通过两秒不透明覆盖渐隐休止。
- 不新增 NPC 玩家碰撞、声音、联网、独立 RAF 或每人定时器；raycast 不截获地图、景点、寻宝点击。
- 角色投影目前关闭。顶点动作修改位置和法线；既有 DepthSSAOPass 复用主场景深度，未改全局后处理或 renderer.info 重置。

## 性能与平台边界

最终 `reports/r50/cpu-submission-benchmark-final.json` 对应 c560681，云端 AMD EPYC 9V74 / Node 24.19.0 / Three r162，六镜头、高低两档各三轮共36轮。每轮按 1/60s 推进1800暖机步与3600采样步；紧循环中的模拟30/60秒不是实际显示30/60秒。数据仅为云 CPU 逻辑/矩阵提交成本，不含 GPU、浏览器整帧、后处理或手机。

- 冷启动第一次人物更新：262.52ms。36轮暖机 p95 范围0.0951–0.2028ms；完整 p50/p95、画质、相机和源文件 hash 在原始 JSON。
- 本组镜头最大34可见实例、9提交批次、26,778三角形估计。另独立覆盖镜头实际提交过38个唯一实例，不把本组34个同屏数与38注册数混淆。
- 单轮最大批次几何缓冲270,906字节、实例缓冲55,296字节、模板 CPU 缓存942,258字节，新增纹理零。它们不是总 GPU 显存实测，也不是多通道整帧 draw calls。
- 独立全 System 压测在并发 CPU 工作下另测冷启动443.68ms，20次重载中位269.47ms、最大323.16ms；卸载中位0.309ms、最大0.633ms。暖机数字不能掩盖这项同步尖峰，冷帧体验尚未通过。
- `cold-optimization-candidate.patch` 明确为未应用方案。它在单独 Adapter 试验把中位241.79ms降至117.73ms，保留954个真实支承查询和5个反例，但不属于交付生产代码，也没有因此宣称预算已通过。

现环境没有可用的真实 GPU/移动设备验证。已知浏览器启动拒绝没有被重试或绕过。因此浏览器 smoke/regression/stepwalk/visual/perf、真实键鼠/触控游览与桌面/手机完整帧 A/B 仍为未验证，不勾选通过。
