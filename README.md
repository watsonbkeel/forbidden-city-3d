# 故宫 3D 虚拟游览

陈华山、陈诺制作的独立非官方浏览器漫游项目，使用 Three.js 与 Vite。
基础建筑由程序生成，部分细化内景按需加载随项目提供的 GLB 资源。
建筑参考公开资料；尺寸、通路和部分陈设包含模型拟合与游戏适配，**不是全宫测绘复原**。

- [在线体验](https://tour.bkeel.com/gugong/)：既有体验地址，线上版本须另核。
- [本地启动](#本地启动)：安装依赖后使用开发服务器。
- [版本与验收边界](#版本与验收边界)：先区分交付、开发候选和线上实例。
- [文档导航](#文档导航)：开发、测试、资料与历史记录。

## 可以体验什么

- 第一人称浏览中轴线、东西六宫、外路、宁寿宫区和御花园。
- 在已有模型道路、院落与可进入殿座间探索；不是所有建筑都开放内景。
- 使用小地图查看位置与朝向，配合界面提供的导航操作。
- 查看程序化建筑与部分可选细化内景；资源加载范围随场景与设置而异。
- 大佛堂包含三佛历史研究模型；新的三尊代码＋原创贴图与八层代码莲座仅供显式私有预览，尚待用户确认，默认不替换已有模型。
- 调整画质、音效和昼夜相关设置，观察游戏人物与场景。

这些是现有系统的功能入口，不表示每座建筑、每条路线或每种设备均已验收。
历史性能数字、建筑清单和各轮修复记录不再堆在首页，见[原 README 归档](README.history-20261110.md)。

## 主要操作

### 桌面

- 点击场景后，用鼠标转向。
- WASD 或方向键移动，Shift 冲刺，空格跳跃。
- M 打开或收起地图；地图还提供屏幕按钮。
- Esc 打开设置或退出当前指针锁定状态，依界面提示继续操作。

### 触摸屏

- 使用左侧虚拟摇杆移动，拖动场景区域转向。
- 使用屏幕上的跳跃、地图和设置按钮。
- 不同浏览器的指针锁定、触摸和性能表现需分别验证。

如果转向未恢复，先关闭挡住场景的面板，再点击场景。
报告问题时请记下设置中显示的构建标识、设备、位置和复现步骤。

## 本地启动

本地开发约定为 Node.js 24 与 npm；仓库提供锁文件。
现有 GitHub Pages 工作流使用 Node.js 20；本地 Node.js 24 的构建结果不能代替该部署环境的兼容性验证。

在仓库根目录执行：

```sh
npm ci
npm run dev
```

默认入口为 http://localhost:5173/gugong/ ，以 Vite 实际输出为准。
端口占用时 Vite 可能选择其他端口；并行工作应显式分配端口：

```sh
npm run dev -- --host 127.0.0.1 --port 5199 --strictPort
```

此时打开 http://127.0.0.1:5199/gugong/ 。
`--strictPort` 遇到占用会失败，不会默默切换到别人的服务。

### 构建与预览

个人工作区可运行：

```sh
npm run build
npm run preview
```

默认产物目录为 `dist/`，预览地址以终端输出为准。
配置中的 `emptyOutDir: false` 不会清除旧产物；不能拿混有旧文件的目录作发行证明。
共享工作区或正式验收应采用全新的独立输出目录，详见[测试与门禁](docs/TESTING.md)。
README 的命令说明不等于对应候选已经完成安装、构建或完整门禁；请查该候选的实际记录。

### 部署路径

- 默认 base 是 `/gugong/`，对应既有体验站的子路径。
- GitHub Pages 项目页使用 `VITE_BASE=/forbidden-city-3d/`。
- 根路径构建可用 `VITE_BASE=/`；部署路径与构建路径必须一致。
- 现有 [Pages 工作流](.github/workflows/deploy-pages.yml) 在推送 main 时自动构建发布，也支持手动触发；合并 main 会触发该既有流程。

开发分支、构建产物、GitHub Pages 和体验站不是同一个版本身份。
本次整理不修改或合并 main，也不触发部署。

私有候选中的三尊均由各自原创 V2 贴图上身与真实八圈代码莲座组成，莲瓣使用本尊原图的单瓣内部纹理，不是把画中的整座贴回去。三尊仅在显式私有研究预览中启用，默认替换关闭；中尊样板尚待用户确认，左右私有预览不等于确认后正式启用。 旧中心 V1 实验资源不再随新版本分发；中心研究加载必须显式选择 `refined-eight-tier-v2`，缺省或旧版本请求会在下载前拒绝并保留程序模型，不会悄悄切换。原实验源码和图像保留在历史恢复材料中。几何、比例、手势和材质仍含拟合，其他陈设不能继承这些结果。CPU 构造、碰撞、构建或软件渲染通过，仅证明相应输入与范围，不代替浏览器、真实设备、全部路线或最终艺术验收。

### 如何理解证据

- 官方文字、照片和图纸是资料来源；拟合尺寸与工程适配须另行标注。
- 人物、作息和陈设不是清代生活史证据，也不代表现场开放情况。
- CPU 几何、碰撞与局部路线检查只证明其具体输入和范围。
- 软件渲染帧率不能代替真实 GPU、桌面浏览器或手机体验验收。
- 旧失败的分诊不等于关闭；后继修复须有对应身份和行为证据。
- 未执行、失败、被拒绝与有限通过必须分别记录。

## 验证与故障排查

详细命令、浏览器选择、端口隔离和测试范围统一见[测试与门禁](docs/TESTING.md)。
Playwright 已列为本地开发依赖，使用锁文件安装，不需要手改测试中的浏览器路径。
完整仓库提供 `npm run test:gate`（`tests/gate.cjs`），覆盖构建、区域、导航锚点、smoke、regression、路线与性能检查。该命令会自行起停 Vite，需可用浏览器与独占端口；先读[测试说明](docs/TESTING.md)。入口存在不表示当前候选已跑过全部门禁，不要用调试跳过项的结果作完整验收。
完整门禁涉及构建与浏览器，执行前应确认环境和资源预算。

- 无法加载：核对 URL 的部署子路径及浏览器控制台中的资源错误。
- 画面卡顿：先降低画质，记录浏览器、设备和构建标识，勿套用旧性能数字。
- 碰撞或路线异常：记录起点、行进方向、位置与实际操作，不以瞬移替代复现。
- 未知是否已修：先查对应版本证据，不把历史快照直接当成当前缺陷清单。

更完整的精度、设备和历史门禁边界见[已知限制](docs/LIMITATIONS.md)。
