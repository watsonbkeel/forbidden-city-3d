# R49 地图宫殿名可读性修复

## 结论与范围

修复东西六宫标签被门名挤掉的根因，并对全部侧区宫殿／宫门执行同一层级与碰撞规则。未修改建筑几何、地点目录或移动逻辑。

用户截图已逐像素查看。旧实现按数据先后顺序、固定中心距离 22×9 排除标签；门往往先出现，十二座六宫主殿在真实七区 mapItems 中全部被排除。标签随后烘焙到底图，放大不会恢复被删宫名，实际长文字框仍会重叠。

新实现：
- 先收集完整候选，主宫殿优先，其次后殿等附属殿，最后宫门。所有区域统一处理，不单独硬编码六宫。
- 用最终屏幕字体测量真实文字宽度，完整矩形加 2 CSS px 间隙做碰撞检查。
- 主殿 13px、宫门 12px，旧址／外观说明另起一行保留，不横跨邻宫。
- 文字在屏幕像素层绘制，不从底图放大低分辨率字形。测试覆盖 742×718 CSS px、800%、DPR 2 边界。
- 缩放／画布尺寸变化重新布局，普通行走和拖动不重建底图。移动端 update 的全图与预览分支互斥，关闭后只切换一次预览尺度。
- 标签点击仍只打开对应资料卡，前往按钮单独触发传送。地图打开／读卡时按住行走仍持续。
- 钦安殿提示改为保留地面观览落点、可沿两侧阶进入虚拟展示，明确不代表现实开放。

## 总览与放大行为

不能声称默认视图已经同时展示十二宫。以下为 300px 宽画布、整图适配系数 0.75 的真实 Noto CJK 字体 CPU 度量；别的窗口尺寸阈值会随适配系数变化。

| 地图倍率 | CSS px／地图单位 | 六宫宫名数 | 全图标签数 | 门名数 | 标签框交叠 |
|---|---:|---:|---:|---:|---:|
| 100% 全图 | 0.75 | 1/12 | 26 | 7 | 0 |
| 200% 默认打开 | 1.5 | 6/12 | 56 | 21 | 0 |
| 400% 分区 | 3 | 12/12 | 126 | 59 | 0 |
| 800% 细节 | 6 | 12/12 | 152 | 69 | 0 |

数量统计是全地图已布局标签，不保证全部处于当前平移视口。分区图可同时辨认十二宫；全图不强行塞入所有文字。提示栏新增“宫殿名优先，放大查看更多”。

## 测试证据

1. 新回归测试初次 5/5 失败，明确失败于景仁宫等被门名挤掉、字体随缩放膨胀，而不是只检查目录字符串。
2. 独立补查最大倍率栅格问题，旧烘焙方式的新测试确实失败于“do not magnify a ~5px baked glyph”；屏幕像素层后通过。
3. 冻结前最终地图行为组合：142/142 通过。包含十二项 R49 地图新测试、compact、gesture、input、资料搜索／选择、四处旧卡片、159 地点真实 ZoneManager／Teleport／碰撞路线集成，以及延禧宫旧 footprint 行为。地点 159 和七项存疑状态保留。
4. CPU 真字体检查：四级缩放的全部标签矩形无交叠；scale≥3 时十二宫均出现。对全侧区所有 hall 移除／保留 gate 比较，四级缩放的宫殿标签集合完全相同，证明宫门不能抢掉宫殿名。
5. compact 旧测试使用 10000×10000 人造标签跨缩放保留，与正确重新排版冲突。改为定位并点击真实太和殿标签，保留拖动、缩放、不误传送与显式前往断言，不弱化行为契约。

## 冻结前补验：正常入口到卡片与独立前往

新增三项用户交互链测试，地图专属 12/12 通过，包含原地图交互和159地点真实落点的最终组合为 142/142 通过。没有改产品实现，也没有伪造任何 label 或放大点击框。

- 桌面用真实 M 键监听器打开；移动端用实际预览按钮点击打开。两者默认 k=2，提示“宫殿名优先，放大查看更多”处于显示状态。
- 默认已布局六个宫名：景仁宫、承乾宫、钟粹宫、永寿宫、翊坤宫、储秀宫。不是十二宫全显。
- 通过真实地图双击监听器从 200% 放大到 400%。十二名为：景仁宫、承乾宫、钟粹宫、延禧宫、永和宫、景阳宫、永寿宫、翊坤宫、储秀宫、太极殿、长春宫、咸福宫。
- 各宫使用真实生产 label 的坐标与字框，用多次不超过 60px 的 pointer 拖动把完整文字框移入视口。逐宫确认该宫名真的进入屏幕层 fillText，而非仅存在于内部候选列表。
- 在真实标签屏幕位置发送 pointerdown／pointerup，逐宫核对固定来源 ID、卡片标题与 modelExperience.teleportTargetName。标签点击不产生任何前往调用；另外点击该卡片前往按钮才产生唯一、同名的目标调用。两端各十二宫全部匹配。
- 标签点击及读卡时保持键盘／摇杆输入，实际控制器位置继续变化。没有用直接调用 showPlace 或 handleMapClick 替代这条链。
- 默认未显示的延禧宫、永和宫、景阳宫、太极殿、长春宫、咸福宫，通过实际搜索输入监听器找到未隐藏按钮，点击打开正确卡片，返回保持 200% 且不触发前往。

逐宫固定 ID 与调用目标在 `map-user-chain.json`。新用户链验证的是生产 Minimap → PlaceCatalog → PlaceInfoPanel → 明确前往回调；真实碰撞落点另外由 159 地点生产 ZoneManager／Teleport 集成覆盖，二者未混称为浏览器验收。
