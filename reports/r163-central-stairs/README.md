# R163 中央楼梯通行修复

基线：`ec50ea010340dc3b04f18ec052f36a05c3862702`。范围：中和殿南北中央御路、保和殿北单殿台明及三层北下台。未上传、未修改或合并 main。

## 根因与修复

原中央御路使用 `NO_GAMEPLAY_WALKABLE` 策略，没有可走坡面，并用横跨整条御路的分段碰撞代理封住通道。现在保留原有石面、雕纹、垂带等全部可视网格，按实际石面范围登记六个游戏坡面，移除中央封行代理。中和殿只保留两侧垂带碰撞。

六个坡面追加到现有三台接地清单，不更改原有记录。保和殿中央石与相接内阶共处同一坡面，身体跨过接缝时仅共享净空区间；原支撑记录、路径覆盖、完整组件校验和身体扫掠碰撞均保留。其他阶梯和外侧通道沿用原接地边界。

这里是游戏通行调整，不表示现实景区当前允许行走御路；当前游客准入仍为未知。

- `node --test tests/r163-central-stones.test.mjs`：155/155 通过。
- 其中 152 条真实 `FirstPersonControls` / `CollisionManager` 移动往返：88 条中央及接缝，64 条左右通路对照。覆盖 10/60Hz、走/跑、W/S；台面 rescue 关闭，不触发跳跃。中央和接缝的脚面与逻辑地面最大差为 0。
- 修前原始中央 24/24 失败；补坡面后增加接地断言暴露 20 项失败；增加偏移接缝断言再暴露 64 项失败。最终均通过。
- 固定基线摘要证明 73 个可视网格及其顶点/法线/UV/索引/变换/材质名完全相同。六条御路范围外的 1577 个碰撞体、101 个可走面记录摘要完全相同。
- 接缝负例覆盖不同坡面、断开区间、无中央所有权、外侧阶梯、跳跃、高空下落、侧向离开和身体扫掠阻挡。
- 独立复核额外执行 52 个限定范围检查，未发现阻塞问题。
- 原始补坡面版 `npm run build` 曾通过。最终接缝版构建在 `vite transforming` 阶段被环境杀死（exit 137）；512MB 限堆重试也因堆内存不足退出（exit 134）。最终构建未验，需集成后串行重新运行。
